# Architecture Decision Records

Use this folder for durable, reviewable technical decisions. Each ADR should state **Status**, **Context**, **Decision**, **Alternatives**, **Consequences**, and **Revision triggers**. Number sequentially: `0001-monorepo-layout.md`, etc. No ADR is considered accepted until explicitly discussed.

Initial candidates: workspace and build boundaries; JS engine and sandbox; TS compilation/import resolution; project bundle and manifest; screen object representation; data sync/conflict resolution; auth/OIDC and sessions; API/capability versioning; GitHub Releases and Play distribution.
